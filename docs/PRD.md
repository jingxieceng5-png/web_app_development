# 產品需求文件 (PRD) - 任務管理系統

## 1. 專案概述

### 背景與動機
在日常工作與生活中，待辦事項繁多且容易遺漏，因此需要一個簡單且集中的系統來記錄、追蹤與管理個人任務，以提升生產力與時間管理效率。

### 目標用戶
- 我（個人使用者）

### 核心價值主張
提供一個直覺且輕量的任務管理系統，讓使用者能快速記錄待辦事項、追蹤完成狀態並透過提醒機制避免遺忘，確保各項事務有條不紊地進行。

## 2. 功能需求

### 1. 新增任務 (Add)
- **使用者故事**: 作為個人使用者，我希望能夠新增一個任務（包含標題與詳細內容），以便快速記錄即將需要執行的事項。

### 2. 編輯任務 (Edit)
- **使用者故事**: 作為個人使用者，我希望能夠編輯已建立的任務內容或到期日，以便在計畫有變或細節更新時，維持任務資訊的準確性。

### 3. 刪除任務 (Delete)
- **使用者故事**: 作為個人使用者，我希望能夠刪除已經作廢或不小心重複建立的任務，以便保持任務列表的整潔與清晰。

### 4. 標記完成狀態 (Mark)
- **使用者故事**: 作為個人使用者，我希望能夠將任務狀態切換為「已完成」或「未完成」，以便我能清楚辨識並享受完成工作的成就感。

### 5. 任務提醒 (Remind)
- **使用者故事**: 作為個人使用者，我希望能夠為特定任務設定提醒（設定到期時間），以便在任務快要到期時，提醒我盡快完成。

## 3. 非功能需求

### 技術限制
- 後端框架: Flask
- 模板引擎: Jinja2
- 資料庫: SQLite

### 效能與安全考量
- 系統應確保在個人使用的資料量下，頁面載入與操作回應時間不超過 1 秒。
- 透過參數化查詢防範 SQL Injection，並透過模板引擎內建功能防範 XSS 攻擊，保護資料安全。

## 4. MVP 範圍

### Must Have (必須具備)
- 新增、檢視、編輯、刪除任務功能 (CRUD)。
- 標記任務狀態為「已完成」/「未完成」。
- 任務列表頁面可清楚顯示狀態。

### Should Have (應該具備)
- 設定任務的到期日與時間。
- 系統內建的視覺提示（例如到期日變紅字）以達到基礎「提醒」作用。

### Nice to Have (未來展望)
- 串接 Email 通知或其他推播方式進行提醒。
- 任務的優先層級 (高、中、低) 設定。
- 任務標籤或分類資料夾。
